## 상황

이 컴퓨터에서 champs.pokedb.tokyo 색인 1,718편을 전부 수집했다.
그 결과가 `data/samples.json` 에 들어가서 **파티 2,155개 · 한카리아스
520마리** 가 됐다.

**그런데 그게 깃허브에 안 올라가 있다.** 원격 브랜치
`claude/ai-design-docs-review-rm4d24` 에는 **파티 711개** 짜리 옛
파일만 있다. 그래서 클라우드 쪽 클로드는 나와 **다른 자료를 보면서**
이야기하고 있다. 실제로 한 번 서로 다른 숫자를 말한 적이 있다.

**네가 할 일은 그 수집 결과를 원격 브랜치에 올리는 것이다.**
그게 전부다. 모델을 고치거나 기능을 더하지 마라.

## 절대 하면 안 되는 것

1. **`data/samples.json` 을 손으로 고치지 마라.** 1MB 넘는 JSON 한
   덩어리다. 사람이(그리고 너도) 눈으로 검산할 수 없다.
2. **`git checkout --ours` / `--theirs` 를 `data/samples.json` 에 쓰지
   마라.** 한쪽을 통째로 버리는 것이라 수집 결과가 날아간다.
3. **`git push --force` 를 쓰지 마라.** 어떤 이유로도.
4. **`git rebase` 를 쓰지 마라.** 합치는 것은 merge 로만 한다.
5. **다른 브랜치에 올리지 마라.** 반드시
   `claude/ai-design-docs-review-rm4d24` 다.
6. **숫자를 추측해서 보고하지 마라.** 전부 실제로 세어서 말한다.

## 순서

### 1단계 — 지금 뭘 갖고 있는지부터 센다

```
git status
git log --oneline -3
python3 samples.py 2>&1 | head -8
```

`samples.py` 가 말하는 파티 수를 적어 둔다. 이게 **기준값**이다.
아래 어느 단계에서든 이 숫자보다 줄어들면 **멈추고 나에게 말한다.**

파티가 2,155개 근처가 아니면 수집 결과가 이 폴더에 없는 것이다.
그 경우 찾지 말고 바로 나에게 "여기엔 711파티짜리 옛 파일뿐입니다"
라고 말하고 멈춰라.

### 2단계 — 안전장치로 사본을 하나 떠 둔다

```
cp data/samples.json data/samples.백업.json
```

이건 커밋하지 않는다. 일이 끝나면 지운다.

### 3단계 — 지금 것을 먼저 커밋한다

아직 커밋 안 된 변경이 있으면 커밋한다. 커밋 메시지는 한국어로,
**무엇을 몇 편 모았는지 숫자를 넣어서** 쓴다. 예:

```
git add data/samples.json
git commit -m "champs 색인 1,718편 전부 수집 — 파티 711 -> 2,155"
```

`data/` 밖의 파일도 고쳐져 있으면 **따로** 커밋한다. 자료와 코드를
한 커밋에 섞지 마라.

### 4단계 — 원격 것을 받아서 합친다

```
git fetch origin claude/ai-design-docs-review-rm4d24
git merge FETCH_HEAD
```

원격에는 내가 클라우드에서 작업한 커밋이 있다 (`combos.py`,
`tests.py`, `README.md`, `docs/` 를 고쳤고 **`data/` 는 안 건드렸다**).
그러니 보통은 충돌 없이 합쳐진다.

**`data/samples.json` 에 충돌이 나면** — 손으로 고치지 말고 이렇게 한다:

```
# 충돌난 파일에서 양쪽 버전을 각각 꺼낸다
git show :2:data/samples.json > /tmp/내것.json
git show :3:data/samples.json > /tmp/원격것.json

# 주소(url)를 열쇠로 합친다. 더 많이 채워진 쪽이 남는다.
python3 merge_samples.py /tmp/내것.json /tmp/원격것.json -o data/samples.json

git add data/samples.json
```

`merge_samples.py` 가 **"합친 결과가 한쪽보다 줄었다"** 라고 하면서
멈추면, 거기서 **너도 멈추고 나에게 그 출력을 그대로 보여 줘라.**
억지로 진행하지 마라.

다른 파일이 충돌하면 코드 쪽이니 평소대로 읽고 합친다. 단
`combos.py` 와 `tests.py` 는 내가 방금 크게 고쳤으니 **원격 것을
살리는 방향**으로 합쳐라 (내용은 §"방금 바뀐 것" 참고).

합친 뒤:
```
git commit           # 메시지는 기본값 그대로 둬도 된다
```

### 5단계 — 줄어든 게 없는지 확인한다 (제일 중요)

```
python3 samples.py 2>&1 | head -12
```

**1단계에서 적어 둔 파티 수보다 줄었으면 멈추고 나에게 말한다.**
합치기는 무엇도 버리지 않아야 한다.

### 6단계 — 검사를 돌린다

```
python3 tests.py 2>&1 | tail -5
```

**"전부 통과" 가 나와야 한다.** 검사는 332개다.

실패가 나오면 **고치려 들지 말고** 실패한 줄을 그대로 나에게
보여 줘라. 자료가 3배로 늘면 표본에서 재는 값들이 움직일 수 있고,
그게 **진짜 발견**일 수도 있다. 테스트를 자료에 맞춰 느슨하게
바꾸는 것은 제일 하면 안 되는 일이다.

### 7단계 — 올린다

```
rm -f data/samples.백업.json
git push -u origin claude/ai-design-docs-review-rm4d24
```

실패하면 네트워크 문제일 수 있으니 2초 → 4초 → 8초 → 16초 기다리며
최대 4번까지만 다시 시도한다. 그래도 안 되면 오류를 그대로 보여 줘라.

## 끝나고 이렇게 보고해라

숫자를 전부 **실제로 세어서** 적는다:

1. 올리기 **전** 파티 수 / 개체 수
2. 올린 **뒤** 파티 수 / 개체 수 / 기술 채워진 개체 / 배분 채워진 개체
3. 출처별 파티 수 (champs 몇 편, pokesol 몇 편)
4. `data/samples.json` 에 충돌이 있었나, 있었다면 `merge_samples.py`
   출력 그대로
5. `python3 tests.py` 마지막 5줄
6. 푸시한 커밋 해시

그리고 아래 두 가지를 **세어서** 같이 알려 줘라. 클라우드 쪽에서
기다리고 있는 숫자다:

```
python3 -c "
import sys; sys.path.insert(0,'.')
import calc, combos, samples
dex = calc.Dex()
byp = samples.by_pokemon(combos.loaded(dex))
rows = byp.get('한카리아스') or []
print('한카리아스 표본', len(rows), '마리')
import collections
c = collections.Counter(r['cls'] for r in rows if r.get('has_evs'))
print('형태별:', dict(c.most_common()))
print()
print('사용률과 자릿수로 어긋난 형태:')
n = 0
for nm, rws in sorted(byp.items(), key=lambda kv: -len(kv[1])):
    if len(rws) < combos.MIN_SAMPLES: continue
    try: pk = dex.find_pokemon(nm)
    except LookupError: continue
    for w in combos.thin_forms(dex, pk):
        n += 1; print(' ', nm, w)
print(' 총', n, '건')
"
```

## 조심할 것 — 이 프로젝트에서 실제로 겪은 함정들

- **`페리퍼` 가 아니라 `패리퍼` 다.** 이름 한 글자가 틀리면 오류가
  안 나고 **그 포켓몬이 조용히 없는 것이 된다.** 이 프로젝트의 고장은
  거의 전부 이런 식이다 — 터지지 않고 조용히 틀어진다. 포켓몬 이름을
  코드에 직접 쓸 일이 있으면 `dex.find_pokemon()` 으로 먼저 확인해라.
- **기술도 배분도 없는 개체**(champs 카드에서 이름·도구만 받은 것)는
  `samples.members()` 가 알아서 뺀다. `has_evs` 표시가 그것이다.
  이걸 건드리지 마라. 안 빼면 못 읽은 개체가 전부 무투자로 세어져서
  한카리아스가 내구형 54%로 나온다.
- **파일을 고치는 동안 수집기가 돌고 있으면 안 된다.** 돌던
  프로세스는 옛 코드를 그대로 쓴다. 실제로 그것 때문에 한 번 통째로
  헛돌았다.

## 방금 원격에서 바뀐 것 (충돌 합칠 때 참고)

- `combos.py` — `split_score()` / `split_moves()` / `thin_forms()` 추가.
  "이 기술이 갈래를 가르는가" 를 `max - min` 이 아니라
  `max / (2등 + 0.05)` 로 재도록 바꿨다. 보고서의
  `← 갈래로 갈린다` 표시도 같은 자를 쓴다.
- `tests.py` — `[33]` 묶음에서 한 마리(한카리아스)만 보던 검사를
  29종으로 넓혔고, 지진·경고 검사 셋을 새로 넣었다.
- `README.md`, `docs/이어받기.md`, `merge_samples.py` — 새 파일 또는
  문서. 원격 것을 그대로 살리면 된다.
- **`data/` 는 하나도 안 건드렸다.** 그러니 `data/samples.json` 이
  충돌한다면 그건 네 쪽 히스토리가 원격과 갈라져 있다는 뜻이고,
  위 4단계의 `merge_samples.py` 로 합치면 된다.

## 이 프롬프트를 쓰고 나서

올라온 뒤에 클라우드 쪽에서 다시 재야 하는 것들 —

- `python3 samples.py --맞추기` — 가정값 넷을 표본 2,155파티로 다시
  맞춘다. **고원 폭을 같이 보고한다.** 최댓값이 고원 안에 있으면
  값을 옮기지 않는다 (`docs/이어받기.md` §5-11).
- `combos.split_score` 문턱 3 이 늘어난 표본에서도 유지되는지.
  703파티에서 29종 전부 5.2 이상이었다.
- `combos.thin_forms` 경고가 몇 종에서 뜨는지. 703파티에서는 39종 중
  4종이었다. 한카리아스 CS형(사용률 36% vs 표본 4%)이 그중 하나다.
