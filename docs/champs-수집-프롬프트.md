### 왜 비어 있었나 — 이게 핵심이다

앞서 작업한 쪽이 "일본 구축기사는 배분을 이미지로 올린다" 고 판단해서
외부 기사 파싱을 뺐다. **그 판단이 틀렸다.** 실제로 본문을 열어 보면
대다수 기사가 **숫자를 글로 적어 둔다.** 실제 예시다.

```
実数値(努力値)：205(32)-107-134(9)-x-132(15+)-97(10)
メガ前：147(2)-162(32)-90- X -90- 156(32)
メガ後：147(2)-197(32)-108- X -90- 180(32)
177(32)-150(0)- 156(22) - x -112(12)-85
165(15)-80-99(7)-162(14)-120-154(30)
調整：215(32)- 176(10) -123(8)- X -105- 138(16)
基礎ポイント H16 A22 B2 S26
```

**H-A-B-C-D-S 순서로 6칸**이고, 괄호 안이 노력치, `x`/`X` 는 안 쓰는 칸이다.
`(15+)` 의 `+` 는 성격 상승, `(0-)` 의 `-` 는 성격 하락으로 보인다
(**이건 추측이다 — 아는 개체 한 마리로 반드시 확인하고 써라**).

앞 작업에서 이걸 놓친 이유는 정규식이 **대시 주변 공백**과 **`x` 자리표시**
를 안 받았기 때문이다. 아래 정규식은 위 예시 7개를 전부 잡고 날짜
(`2026-09-10`)·레이팅 나열(`2228→2140→…`)은 안 잡는 것을 확인했다.

```python
FIELD = r'(?:\d{1,3}\s*(?:[（(]\s*\d{1,2}\s*[+＋\-－]?\s*[）)])?|[xX×ｘ])'
DASH  = r'\s*[-−ー–—]\s*'
STATLINE = re.compile(FIELD + (DASH + FIELD) * 5)
```

### 노력치가 괄호에 없어도 실능만 있으면 복원된다

`calc.real_stat(종족값, 노력치, 종류, 성격)` 이 **게임 화면과 6/6 일치
확인된 계산식**이다. 노력치는 0~32 뿐이라 33개를 다 넣어 보면 역산된다.
직접 왕복 시험해서 **30/30 복원**을 확인했다.

```python
def invert_ev(base, real, kind, nature):
    hits = [ev for ev in range(33)
            if calc.real_stat(base, ev, kind, nature) == real]
    return hits[0] if len(hits) == 1 else None   # 여러 개면 확정 못 함
```

주의할 것:

* **성격을 모르면** 25개 성격을 다 넣어 보고, 6칸이 전부 맞아떨어지는
  성격만 남긴다. 하나로 안 좁혀지면 **그 개체는 배분을 비워 둔다.**
  (성격을 잘못 고르면 배분이 통째로 틀린다.)
* `メガ前` 은 **기본 폼 종족값**으로, `メガ後` 는 **메가 폼 종족값**으로
  역산해야 한다. 섞으면 안 된다. `メガ前` 쪽을 쓰는 것이 안전하다.
* 합이 66 을 넘으면 그 개체는 버려라. 챔피언스는 한 칸 32 · 합 66 이다.
  본편 표기(252 등)가 섞여 들어오면 여기서 걸린다.

### 기술은 욕심내지 마라 — 여기서 한 번 틀렸다

앞 작업에서 산문에서 기술을 줍는 전략을 짜서 돌려 봤고 **틀린 값이
나왔다.** 한 편(reboiona, M-5 최종2위)을 손으로 대조한 결과다.

* 개체 구획은 `・メガルカリオ` 처럼 가운뎃점 제목으로 나뉘는데, 항목
  표지(`技構成`·`持ち物`·`性格`)는 한 개도 없다.
* `・ガブリアス` 구획은 **버린 예전 구성과 최종 구성을 둘 다** 서술한다.
  앞에서 4개를 집으면 버린 구성을 집는다.
* `・メガリザードンY` 구획 안에 **상대 가브리아스의 기술**이 먼저 나온다.
* 구획을 안 나누면 더 나쁘다. 구축경위에 적힌 가상적이 파티원으로 잡혀
  셋이 같은 기술 4개를 나눠 가졌다.

그래서 **기술은 구조가 명확할 때만** 넣어라 — 표(`<table>`),
`data-*` 속성, 또는 `技構成` 같은 표지가 실제로 있는 경우. **애매하면
`"moves": []` 로 비워 둬라.**

**배분만 있어도 값을 한다.** `samples.py` 는 배분만 있는 개체를
`--맞추기` 의 성격·도구 쪽과 형태 세기에 쓴다. 기술은 `--쌍` 에만 필요하다.
**틀린 기술을 넣으면 `--쌍` 표가 존재 이유를 잃는다. 없는 것이 낫다.**

### 반드시 피할 함정

`forms.spread_class({})` 는 `"-"`(무투자) 를 돌려준다. **못 읽은 것과
무투자가 같은 값이 된다.** `"-"` 는 실재하는 형태라서, 배분을 못 읽은
개체를 그냥 넣으면 공격형이 통째로 무투자로 분류되고 `--맞추기` 와
`combos.py` 가 **조용히** 틀어진다. 실제로 한 번 오염됐다
(한카리아스 형태가 내구 54% 로 나왔다. 사용률은 AS 47% 다).

`samples.py` 가 이미 `has_evs` 로 막아 두었으니 **배분을 못 읽었으면
`"evs": {}` 로 두면 된다.** 억지로 0 을 채워 넣지 마라.

### 132편은 색인의 전부가 아니다 — 여기부터 시작해라

앞서 `--목록 200` 으로 돌려서 132편이 나왔다. **그건 끝이 아니다.**
`collect_cards` 가 `?rule=0` **한 가지 필터만** 훑고 한 쪽이 비면 바로
멈추게 돼 있었다. 그런데 받아 둔 132편에 룰이 **M-3·M-4·M-5**, 시즌이
**S4·S5** 로 섞여 있다. 색인이 여러 룰·시즌을 담고 있다는 뜻이다.

그래서 세 가지를 미리 고쳐 뒀다.

* `--살펴보기` — 검색 페이지의 `select`·`option`·검색 링크·총 건수(`N件`)
  를 찍어 준다. **모으기 전에 무엇으로 좁힐 수 있는지 확인하는 자리다.**
* `collect_cards` 가 한 쪽 비었다고 바로 안 멈춘다 (세 쪽 연속이어야 끝).
* `--전부` / `collect_all` 이 `rule` 을 0부터 올려 가며 훑는다.
  `extra` 로 `&season=5` 같은 질의를 덧붙일 수도 있다.

### 할 일

1. **`python fetch_champs.py --살펴보기` 를 제일 먼저 돌려라.**
   찍혀 나오는 것을 보고 이 셋을 확정해라.
   * 총 건수 표기(`N件`)가 있나 — 있으면 **몇 편을 받아야 하는지 그 숫자다**
   * `rule` 이 몇 가지인가 (`select`/`option` 값)
   * 시즌·룰·순위·정렬 파라미터가 따로 있나 (`select name=` / 검색 링크)
   * 마지막 쪽 번호가 몇인가
   받은 HTML 은 `raw/champs_search.html` 에 저장되니 직접 열어 봐도 된다.
2. 1번에서 알아낸 파라미터로 **색인을 통째로** 훑어라.
   `--전부 5000` 이 `rule=0..11` 을 훑지만, 파라미터 이름이 다르면
   `collect_all(rules=..., extras=[...])` 를 그에 맞게 불러라.
   **받기 전에 "색인에 몇 편이 있다" 를 먼저 보고해라.**
3. `python fetch_champs.py --구조 <기사 주소 하나>` 로 카드 구조가
   깨지지 않았는지 확인 (이미 되는 부분이다).
4. 카드마다 외부 기사를 따라가서 위 형식으로 **배분**을 뽑아라.
   `STRATEGIES` 에 전략을 추가하는 방식으로 하고, 어느 전략으로 읽었는지
   `parsedBy` 에 남겨라.
5. 개체를 이름으로 카드와 합쳐라 (`merge_card`). 카드가 주는 순위·룰·
   트레이너·도구는 살리고 배분·성격·기술을 채운다.
6. 사이트에 부담 주지 마라 — 요청 간격 2초, gzip 켜기, 10편마다 중간 저장
   (`fetch_champs.py` 에 이미 다 있다).

### 넣는 형식

`data/samples.json` 의 `parties` 배열에 이어 붙인다. 기존 champs 파티는
**갈아끼워라** (`url` 이 같으면 교체). 이름은 **일본어 그대로** 넣으면
`data/names_ja.json` 이 한국어로 잇는다.

```json
{"parties": [
  {"source": "champs",
   "url": "외부 기사 주소",
   "season": 6, "rule": "M-6", "rank": 12,
   "trainer": "트레이너명",
   "publishedAt": "2026-09-10T12:00:00Z",
   "title": "기사 제목",
   "parsedBy": "실능(努力値) 나열",
   "members": [
     {"name": "ガブリアス", "item": "オボンのみ", "ability": "さめはだ",
      "nature": "いじっぱり",
      "evs": {"H": 32, "B": 22, "D": 7, "S": 5},
      "moves": ["じしん", "ドラゴンテール", "ステルスロック", "つるぎのまい"]}
   ]}
]}
```

`"source": "champs"` 를 반드시 넣어라 — 그게 있어야 표본 값어치를 3배로
본다 (`samples.SOURCE_WEIGHT`). champs 는 순위가 100% 붙어 있어서
그만큼 값이 높다.

### 마지막으로

`fetch_champs.py` 의 docstring 을 **네가 알아낸 것으로 고쳐 써라.**
특히 "배분은 거의 이미지다 / 노력치 표기가 0건이었다" 는 **틀린 서술**이니
지워라. 다음 사람이 또 같은 판단을 하면 안 된다.
같은 이유로, 못 읽은 형식이 있으면 **왜 못 읽었는지** 남겨라.
