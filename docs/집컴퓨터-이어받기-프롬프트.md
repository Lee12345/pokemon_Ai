## 1. ★ 제일 먼저 확인할 것 — 잃어버린 수집 결과

**이 컴퓨터에서 예전에** champs.pokedb.tokyo 색인 1,718편을 전부 수집해서
`data/samples.json` 을 **파티 2,155개 · 한카리아스 520마리** 로 만든 적이
있다. 그런데 **그게 깃허브에 안 올라갔다.** 저장소에는 아직 **파티 711개
(유효 703개)** 짜리 옛 파일뿐이다.

**그런데 지금 이 컴퓨터에 프로젝트 폴더가 없었다.** 그러니 그 수집 결과가
아직 어딘가 남아 있는지, 아니면 사라졌는지 **아무도 모른다.**

→ **추측하지 말고 직접 찾아봐라.** 예를 들어 —

    # 사용자 폴더 아래에서 옛 저장소나 samples.json 을 찾는다
    find ~ -name "samples.json" -not -path "*/pokemon_Ai/data/*" 2>/dev/null
    find ~ -maxdepth 4 -type d -name "pokemon_Ai*" 2>/dev/null

찾았으면 **파티 수부터 세고** (추측하지 마라) 사용자에게 보고한다:

    python3 -c "import json,io; d=json.load(io.open('<경로>',encoding='utf-8')); print(len(d['parties']))"

- **2,155개짜리를 찾았다** → `docs/수집결과-올리기-프롬프트.md` 를 그대로
  따라서 올린다. 거기 **하면 안 되는 것 6가지**가 적혀 있다
  (손으로 고치지 마라 / `git checkout --ours|--theirs` 쓰지 마라 /
   force push 금지 / rebase 금지 / 다른 브랜치에 올리지 마라 /
   숫자를 추측해서 보고하지 마라). 반드시 읽어라.
- **못 찾았다** → **사라진 것이다. 사용자에게 그렇게 말해라.**
  "있을 것이다" 라고 둘러대지 마라. 다시 모으려면
  `docs/champs-수집-프롬프트.md` 가 있고, 이 컴퓨터는 champs 접속이 되므로
  가능하다 (색인 1,718편 · 2초 간격이라 한참 걸린다).
  다시 모을지는 **사용자가 정한다.** 네가 멋대로 시작하지 마라.

자료가 703개든 2,155개든 **프로그램은 돌아간다.** 표본은 경향성을 보려고
모으는 것이지 없으면 안 되는 것이 아니다. 다만 문서의 숫자들이 703파티
기준이라는 것만 기억해라.

## 2. 이 프로젝트가 뭐냐

포켓몬 **챔피언스**(본편 아님)에서 **"지금 이 상황에서 무엇이 최선의 수인가"**
를 알려주는 도구다. 그래픽은 없고 전투 규칙과 계산만 한다.

사용자는 **전공자가 아니다.** 용어 늘어놓지 말고 평범한 한국어 존댓말로 쓴다.

| 파일 | 하는 일 |
|---|---|
| `calc.py` | 데미지 계산기 (한 방) |
| `best.py` | 기술 비교 · 스피드 |
| `battle.py` | 턴 루프 · 교체 · 압정 · 날씨 · 도구 · 메가 |
| `scout.py` | 상대를 확률 분포로 |
| `forms.py` `combos.py` `samples.py` | 형태 추론 · 기술 조합 · 구축기사 표본 |
| `pick.py` | 6단계 선출 (6마리 중 3마리 + 선봉) |
| `search.py` | 7단계 — 이번 턴의 수 |
| `live.py` | 실전 도구(글자판) + **창과 같이 쓰는 규칙** |
| `gui.py` | 실전 도구(창) |
| `faketk/` | 가짜 tkinter — 창을 화면 없이 돌려 보는 장치 |

1~7단계 + 실전 도구까지 다 됐다. **지금은 실전에 쓸 수 있는 상태다.**

실행 파일(윈도우 exe)은 `.github/workflows/build.yml` 이 만든다.
`main` 에 푸시할 때 자동으로 돌고, 작업 브랜치에서 돌리려면
Actions 탭 → 「실행 파일 만들기」 → Run workflow 에서 브랜치를 골라 누른다.

## 3. 네가 반드시 지켜야 할 것 (CLAUDE.md 요약 — 원문을 꼭 읽어라)

1. **항상 의심한다.** 사용자가 직접 정한 규칙이다:
   *"토큰을 좀 더 잡아먹더라도 항상 의심해. 이건 필수과정이야."*
2. **숫자를 내놓기 전에, 그 숫자를 만든 입력이 실제로 쓰였는지 먼저 센다.**
3. **놀라운 결과가 나오면 설명을 붙이기 전에 의심한다.**
   설명을 먼저 붙이면 그 설명이 검증을 대신해 버린다.
4. **사용자가 되물으면 그건 거의 항상 맞는 지적이다.**
   이 저장소에서 사용자가 되물은 건은 지금까지 **전부** 실제 결함이었다.
   **하나도 빠짐없이 전부다.**
5. **의심은 말이 아니라 코드로 남긴다.** 경고를 띄우거나 검사를 만든다.
6. **검사가 깨졌을 때 검사를 느슨하게 만들지 않는다.** 전제가 틀렸으면
   전제를 고친다. 값이 움직인 것이면 그게 진짜 발견이다.
7. 커밋 메시지는 한국어로, **무엇을 왜 바꿨는지와 숫자**를 적는다.
   틀렸다가 고친 것이면 틀린 과정도 적는다.
8. **갈림길은 사용자에게 물어본다.** 물을 때는 **근거가 될 숫자를 재서**
   같이 내민다. 의견만 내밀지 않는다.

### 이 저장소가 고장나는 방식은 하나다 — **조용히 틀어지는 것**

터지지 않는다. 그냥 조금씩, 때로는 통째로 틀린 답을 낸다.
새 기능을 넣을 때마다 먼저 물어라: **"이게 조용히 틀어질 수 있는 자리인가."**

실제로 그렇게 잡힌 것들 — **전부 사용자가 되물어서 나왔다.**

| 무엇이 틀어져 있었나 | 크기 |
|---|---|
| 아머까오 도구 셋(99%)이 미구현이라 맨몸으로 싸움 | 26.6% → 43.2% |
| 물붓기가 장식이었다 (`types_override` 가 계산에 안 감) | 효과 0 |
| 상대를 한 마리로만 볼 수 있었다 (벤치가 계산에 없음) | 한 수에서 **64%p**, 순위 뒤집힘 |
| 나와 있는 놈이 1번이 아니면 계획이 통째로 버려짐 | 세 계획이 **결과까지 동일** |
| 풍선이 땅 기술을 못 막음 (반만 붙은 도구) | **100% → 0%** |
| 메가가 한 파티에 셋까지 나옴 | **34.2% → 0.0%** |
| 메가를 "선봉만" 으로 굳혀서 아껴 두는 수를 표현 못 함 | 수 자체가 없었음 |
| 칸을 눌러도 후보가 안 떠서 특성을 못 고름 | 기능 자체가 사용 불가 |
| 속도를 `8.6ms` 로 적어 놨는데 다시 재니 `5.1ms` | 잰 방법을 안 적어서 |

**특히 마지막 둘을 봐라.** 숫자를 적을 때는 **잰 방법도 같이 적는다.**
그리고 화면에 보이는 것과 계산이 쓰는 것이 갈라지는 자리를 늘 의심해라.

## 4. 지금 열려 있는 일

1. **수집 결과 찾기/올리기** (위 §1). 제일 먼저.
2. **실전 투입.** 사용자가 게임하면서 따라 두고, 진 판
   (`내기록/대전기록/*.txt`)을 가져와 왜 졌는지 되짚는다. **이게 최종 목표다.**
3. 동반 출현(`samples.partners`)을 `pick.py` 에 연결 — 상대 6마리를 보고
   어느 3마리를 낼지 예측.
4. 8단계 — 자가발전.
5. 아직 안 붙은 도구 효과 (`battle.APPLIED_ITEM_KINDS` 밖) —
   선제공격손톱 · 큰뿌리 · 조임밴드 · 메트로놈 · 과사열매 · 아름다운허물.

### 아직 확인 못 한 가정값

`calc.py` `CONFIG` 에서 `# 미확인` 이 붙은 것들. 전부 본편 값을 가져다 쓴 것이다.
스크린 감소율(1/2) · 날씨 타입 배율(1.5/0.5) · 필드 타입 배율(1.3) ·
압정 수치 · 상태이상 수치 전반.
**실전에서 계산이 어긋나면 여기부터 의심한다.**

사용자가 확인해 줘서 닫힌 것: 자속 1.5 · 급소 1.5 · 화상 물리 반감 0.5 ·
마비 스피드 0.5.

## 5. ★ 너만 할 수 있는 것 — 창을 진짜로 보기

클라우드 쪽은 이것들이 **안 됐다.**

| | 클라우드 | 너 |
|---|---|---|
| `champs.pokedb.tokyo` | 403 | **된다** |
| `yakkun.com` | 403 | **된다** |
| `tkinter` (창) | **없다** | 있을 것이다 |
| 화면 | 없다 | 있다 |

**창(`gui.py`)을 만든 사람은 그 창을 한 번도 못 봤다.** 컨테이너에 tkinter도
화면도 없어서, `faketk/` 라는 가짜 tkinter 로 "터지지는 않는가" 만 확인했다.
**생김새 · 글꼴 · 배치 · 단추가 실제로 눌리는지는 아무도 모른다.**

    python3 gui.py

로 띄워서 사용자와 같이 봐라. 특히 **내 6자리 + 상대 6자리로 커진 뒤
화면에 다 들어가는지**가 제일 걱정되는 부분이다. 잘리거나 스크롤이
이상하면 고쳐라.

창을 고치면 `gui.py --점검` 에도 **칸을 채워 보는 줄을 같이 넣어라.**
그게 유일한 자동 방어선이다.

## 6. 하지 말아야 할 것
