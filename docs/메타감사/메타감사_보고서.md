> 읽는 법 — **"감사자가 말했다" → "코드에 있다" → "논리적으로 틀렸다" → "실행하면 결과가 달라진다" → "실제 추천이 달라진다"** 는 서로 다른 다섯 단계다.
> 이 보고서의 판정은 대부분 4단계까지만 간다. **5단계(실제 추천·승률 영향)를 잰 항목은 하나도 없다.**

## 0. 먼저 — 이 메타감사 자체의 한계

- **나도 Claude 계열 모델이다.** Claude 감사 결과를 "확인" 한 것은 완전히 독립적인 증거가 아니다. 같은 식으로 착각할 수 있다.
  그래서 확인할 때마다 **대조군**(정상이어야 하는 경우)을 같이 돌렸고, 출력 숫자를 그대로 적었다.
- 내 첫 순풍 실험은 **기대값이 틀렸다** (하마돈 속도를 2배 해도 134로 드래펄트 194보다 느렸다 — 결과가 "버그"처럼 보였지만 사실 실험이 무의미했다). 고쳐서 다시 했다. 이 저장소의 교훈(CLAUDE.md §8 "시험 자체가 무의미했던 적") 그대로다.
- GUI·화면 읽기·데이터 수집기는 **실행하지 않았다.**

1. **1번이 나와 있으면 후보 수가 아예 실행되지 않는다** (Claude-A1). 후보 5개가 씨앗 20개에서 **완전히 같은 판**을 만든다. → **V_N 에서 고쳐짐** (재현으로 확인).
2. **벤치 포켓몬은 적어 준 기술이 아니라 사용률 기술을 쓴다** (Claude-A2 / GPT-3). 아머까오가 없는 브레이브버드를 423~1131회. → **V_N 에도 남아 있음** (재현으로 확인).
3. **정책이 한 번 고른 기술을 판 끝까지 반복한다** — 상대(Claude-A3) **뿐 아니라 내 쪽도** (새 발견). 200판 중 2가지 이상 쓴 판 0. → **V_N 에도 남아 있음**.
4. **순풍·트릭룸·반감열매가 전투 루프에 연결되어 있지 않다** (Claude-A5·A7). → **V_N 에도 남아 있음**.
5. **공격기 부가효과(용성군 특공 −2 등)가 적용되지 않는다** (Claude-A4). → **V_N 에서 고쳐짐**.
6. **matchup_table 캐시가 이름만 보고 답을 돌려준다** (OpenCode-A8). → 두 버전 모두 남아 있으나 **실전 추천 경로(live/gui)에는 닿지 않는다** (선출 `pick.py` 에만).

세부 확인:

- **ChatGPT가 본 버전.** ChatGPT가 인용한 `live.Fight.state()` (HP·active 만 돌려줌) 와 `search.rollout` 의 `my_party[0]` 은 **V_H 와 정확히 일치**하고, V_O 에는 그 파일이 없으며, V_N 에서는 `my_party[ai]` 로 바뀌었다. 그러므로 ChatGPT는 V_H(또는 V_H 와 9-19 사이) 를 읽었다고 보는 것이 맞다. 단 **추정**이다.

## 3. Repository Version Confounders

**여기가 이 메타감사에서 가장 중요한 절이다.**

1. **OpenCode 는 실전 경로가 없는 코드를 봤다.** V_O 에는 `search.py`·`live.py`·`gui.py`·`paths.py` 가 없다. 그러므로 OpenCode 가 "live 정보 제한", "CLI end-to-end" 를 사각지대로 적은 것은 **그 버전의 코드에서 나온 것일 수 없다.** 반대로 OpenCode-A5(`build_plans` 후보 제한) 는 V_O 에서는 주 경로였지만, V_H 에서는 실전 탐색이 `search.candidate_actions` (내 기술 4개 + 교체 전부) 로 옮겨가서 **선출·연구 도구에만** 남았다.
2. **반감열매는 버전마다 다른 코드다.** V_O 에서는 반감열매가 데미지 표(`calc.py`, "반감" 27회) 쪽에만 있었고 턴 루프 도구 규칙(`APPLIED_ITEM_KINDS`) 은 아직 없었다 (그 뒤 `f00beb9` 에서 들어옴). OpenCode-A3 과 Claude-A5 는 **같은 현상을 다른 코드에서 본 것**이다.
3. **V_N 이 여러 항목을 고쳤다.** 날짜로 보면:
   - `13f22b6` (09-19) — 상대 6마리 · `lead=` · `my_party[ai]` → A1 · GPT-2
   - `797d8ff` (09-22) — 공격기 추가 효과 → A4
   - `7d57d5e` — "대전 경고를 창까지" → A9 (코드에 `sink` 로 전달하는 것 확인, 실행 안 함)
   - `0f3e992` (09-23) — 상태이상·랭크·날씨/필드 입력 → GPT-1/A6 일부 (실행 안 함)
   - live 의 상대 HP 가 칸별로 저장됨 → GPT-4 / A10(상대 HP) (코드 확인)
   이 수정들이 감사 결과를 보고 한 것인지, 따로 찾은 것인지는 **알 수 없다.**
4. **V_N 의 테스트.** 이 컨테이너(리눅스, 화면 없음)에서 **936개 통과 · 2개 실패** 뒤, 윈도우 전용 `powershell` 을 못 찾아 중단됐다 (3분 39초, 종료 코드 1). 실패 2개는 창·화면 읽기("화면을 못 찍었습니다"). 환경 탓일 가능성이 높지만 **확인하지 않았다** — "V_N 은 테스트를 통과한다" 고 말할 수 없다.
5. **main 에서 고치면 안 된다.** 지금 이 작업 브랜치와 `main` 은 V_H 다. 여기서 무엇을 고치든 V_N 의 50 commit 과 충돌하거나 이미 고친 것을 다시 고치게 된다.

항목별 버전 민감도는 4절 표의 "버전" 칸에 적었다. `V_H✔ V_N✔` 는 "그 버전에서 재현됨", `V_N✗` 는 "그 버전에서 고쳐짐(재현 안 됨)", `(코드)` 는 실행 없이 코드만 봤다는 뜻이다.

## 10. Test Blind Spots

V_H 에서 491개 전부 통과를 **다시 확인했다** (136초). 테스트가 **틀린** 것은 아니다. 문제는 **무엇을 재느냐**다.
