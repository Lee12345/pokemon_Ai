# pokemon_Ai

포켓몬 챔피언스의 전투 방식을 코드로 옮기고, 그 위에서 **"지금 이 상황에서 무엇이 최선의 수인가"** 를 알려주는 도구를 만드는 프로젝트.

그래픽은 구현하지 않는다. 전투 규칙과 계산만 다룬다.

---

## 지금 상태

- [x] **1단계 — 게임 데이터 확보**
- [x] **2단계 — 실전 사용률 데이터 갱신**
- [x] **3단계 — 데미지 계산기**
- [x] **4-A — 스피드 비교 + 기술 일괄 비교** ← 지금 여기까지 됨
- [x] **4-B — 1대1 턴 루프 + 날씨·필드** (`battle.py`)
- [x] **4-C — 상대를 채용률 분포로 보기** (`scout.py`)
- [ ] 5단계 — 대전 중 교체 + 압정
- [ ] 6단계 — 선출 (6마리 보고 3마리 고르기)
- [ ] 7단계 — 여러 턴을 내다보는 AI
- [ ] 8단계 — 자가발전

> **다음 한 수는 1대1 턴 루프다.** 지금 못 하는 것들 — 변화기, 회복, 1회용 도구,
> 탈·지구력 같은 특성, 2턴기·연속히트, 날씨·필드 — 의 원인이 전부 "턴이 없다" 하나로
> 수렴하기 때문이다. 상위 20마리 중 **1위 도구가 계산에 아무 효과도 못 내는 경우가 9마리**,
> **회복기·랭크업기를 20% 이상 채용하는 경우가 12마리**다.
> **날씨·필드는 턴 루프와 같이 넣는다.** 하마돈(4위) 모래날림 99.8%, 고릴타(10위)
> 그래스메이커 99.8% — 나오기만 하면 깔리므로 선택이 아니라 기본값이다.
> 반대로 **대전 중 교체는 한 칸 미룬다.** 1대1은 손으로 검산되지만 3대3은 안 되기 때문이다.
> 선출(6마리 중 3마리)은 대전 시작 전의 결정이라 그 뒤로 뺐다.
> 근거와 순서는 [docs/ai-design.md](docs/ai-design.md) 6장.

**AI를 어떻게 만들 것인지는 [docs/ai-design.md](docs/ai-design.md) 에 정리해 뒀다.**
새 대화에서 이어서 작업할 때 그 문서부터 읽으면 된다.

## 폴더 설명

```
calc.py           데미지 계산기 — 한 대 때리면 얼마 들어가나
best.py           한 턴 최선수  — 누가 먼저 때리고, 어느 기술이 제일 좋은가
battle.py         여러 턴       — 턴을 끝까지 돌려 본다 (용의춤·회복기 포함)
scout.py          상대 추정     — 상대를 하나가 아니라 사용률 분포로 본다
tests.py          계산이 맞는지 검사하는 프로그램
build_data.py     게임 데이터를 받아서 정리하는 프로그램
build_usage.py    실전 사용률을 한국어로 연결해 붙이는 프로그램
data/             정리된 결과물
raw/              내려받은 원본 (자동 생성, 지워도 됨)
```

## 계산기 쓰는 법

```
python calc.py 메가보만다 이판사판태클 하마돈
```

이름만 넣으면 **실전에서 제일 많이 쓰는 성격·노력치·도구**를 자동으로 적용해서 계산한다.
그냥 `python calc.py` 만 치면 하나씩 물어보는 방식으로 쓸 수 있다.

나오는 결과는 이렇다.

```
  메가보만다  →  하마돈
  기술: 이판사판태클 (노말→비행 물리 위력144)
  상성: 보통  /  자속 있음
  공격 216  vs  방어 151   상대 HP 215

  데미지  117 ~ 138   (HP의 54.4% ~ 64.2%)
  결론    확정 2타
  · 스카이스킨: 노말 → 비행, 위력 1.2배
  급소면  175 ~ 207   (81.4% ~ 96.3%)  →  확정 2타
```

계산을 고쳤으면 `python tests.py` 를 돌려서 깨진 데가 없는지 확인한다.

> 이름만 넣었을 때 **1위 도구가 메가스톤이면 메가로 계산한다.** 사용률은 기본 폼 기준으로
> 집계되고 메가는 '도구 채용률'로만 나타나기 때문이다 (보만다나이트 97.7% → 메가보만다).
> 채용률이 낮으면(한카리아스나이트Z 35.3%) 그 숫자를 같이 적어 준다.

## 최선수 추천 쓰는 법

```
python best.py 메가보만다 하마돈
python best.py 메가보만다 하마돈 이판사판태클 지진 용의춤
```

기술을 직접 적으면 그것만 비교하고, 안 적으면 사용률 상위 기술을 대신 쓴다.
`--트릭룸` 을 붙이면 느린 쪽이 먼저 움직이는 것으로 본다.

나오는 것은 세 덩어리다.

**1. 스피드 비교** — 내가 먼저 때리는가. 상대 배분은 모르므로 사용률로
**"상대 스피드가 얼마일 수 있는지"와 "내가 더 빠를 확률"**까지 같이 낸다.

```
[스피드]  나 172  vs  상대 288   →  상대가 먼저 때린다
  상대 배분은 사실 모른다. 사용률로 보면 상대 스피드는 143 ~ 288 사이다.
    내가 더 빠를 확률  약 0.6%
    · 구애스카프 61.3% → 스피드 214 ~ 288  (이 경우 내가 후공)
    · 스피드 도구 없음 38.7% → 스피드 143 ~ 192
```

**2. 기술 일괄 비교** — 내 기술과 상대 기술을 각각 표로. 데미지·명중률·확정 몇 타와
'이번 턴에 쓰러뜨릴 확률'(명중률까지 곱한 값)이 붙는다.

**3. 대면 결론** — 이 대면을 이기는가.

```
[대면 결론]
  추천 기술   이판사판태클   (확실히 이김)
    · 내가 먼저 때린다  (스피드 172 vs 67)
    · 내가 상대를 쓰러뜨리는 데 2번 (확정)
    · 상대의 제일 아픈 수 '얼음엄니' 로는 나를 쓰러뜨리는 데 2번 (확정)
    · 상대 기술 중 나에게 아예 안 통하는 것 — 지진(97.7%), 땅가르기(0.5%)
    ! 이판사판태클: 준 데미지의 1/3 를 자신도 받는다
```

선공이면 같은 타수라도 이기고, 후공이면 한 번 더 빨라야 이긴다.
난수 폭까지 보고 **확실히 이김 / 난수 싸움 / 확실히 짐** 으로 가른다.
**추천 기술은 데미지가 제일 센 것이 아니라 대면을 이기는 것으로 고른다.**

`!` 가 붙은 기술은 위력 숫자만으로는 안 되는 기술이다 (공격기 335개 중 55개).
2턴 기술·연속 히트·고정 데미지·위력 가변·반동·날씨 의존을 게임 설명문에서 찾아낸 것이다.
**배율을 찍어 넣지는 않는다.** 아는 척해서 틀린 값을 넣느니 모른다고 말하는 편이 낫다.

아직 못 하는 것: 변화기의 값어치(4-B) · 급소 · 교체 · 날씨/필드 ·
선제공격기에 붙은 조건(만나자마자는 나온 첫 턴만).

## 여러 턴 돌려보기

```
python battle.py 메가보만다 하마돈
python battle.py 메가보만다 하마돈 --기록      한 판을 턴별로 찍어 본다
```

`best.py` 는 한 턴만 본다. 그래서 데미지가 0인 기술(용의춤·날개쉬기·칼춤)에는
점수를 못 매긴다. 이건 턴을 끝까지 돌려서 답을 낸다.

```
  계획                              승률    이겼을 때 남는 HP   남는 랭크           남는 몸
  용의춤 → 용의춤 → 이판사판태클    100.0%  38%                 공격+2 스피드+2     98
  역린                              100.0%  89%                 없음                89
```

**내놓는 답이 승패가 아니라 '끝났을 때의 상태' 다.** 승률이 같아도 남는 몸이 다르다.
쌓아둔 랭크는 상대가 쓰러져도 남아서 **후속 포켓몬까지 따라가기 때문**이다.

반영한 것 — 변화기 효과(설명문에서 읽어낸다), 날씨·필드(하마돈 모래날림 99.8% 등
등장만으로 까는 특성 포함), 1회용 도구(자뭉열매·기합의띠·먹다남은음식),
턴이 있어야 되는 특성(따라큐 「탈」, 브리두라스 「지구력」, 한카리아스 「까칠한피부」,
드닐레이브 「열교환」, 「옹골참」), 명중률·급소·반동,
그리고 상태 이상 — 화상·마비·독·맹독(누적)·잠듦·졸음(하품)·얼음·혼란.

> 상태이상 면역은 출처가 갈린다. **특성 면역 9개와 기술별 타입 면역 4개는 게임
> 설명문에 적혀 있어서 읽어 쓴다.** 반면 '불꽃타입은 화상에 안 걸린다' 같은
> 타입 자체의 면역은 게임 데이터 어디에도 없어서 본편 규칙을 가정했고,
> 걸릴 때마다 경고가 뜬다. 참고로 `잠자기` 는 게임 설명문이 **2턴**이라
> 본편(3턴)과 다르다 — 게임 쪽을 따랐다.

> 상대 기술은 **채용률 상위 4개**를 들고 있다고 본다. 이건 '각각 많이 쓰이는 4개' 지
> '같이 쓰이는 4개' 가 아니다 (한카리아스는 AS형이면 드래곤테일을 잘 안 든다).
> 형태별 구성은 직접 뛰면서 쌓아야 할 정보다. 자세한 것은
> [docs/ai-design.md](docs/ai-design.md) 6장.

## 상대를 분포로 보기

```
python battle.py 메가보만다 하마돈 --분포
python battle.py 메가보만다 하마돈 --분포 --봤다 얼음엄니
```

상대가 뭘 들고 있는지는 모른다. 대신 **사용률이 있다.** 매 판 상대를 채용률대로
새로 뽑아서 싸우므로, 나오는 승률이 '실제로 만날 상대들을 평균한 값' 이 된다.

제일 쓸모 있는 건 이 부분이다.

```
[졌을 때 상대는 이랬다]
  · 기술 '얼음엄니' — 졌을 때 100% 에 있었다 (평소 5%, 21.4배)
```

평소 잘 안 나오는 것이 위에 뜨면 **운 나쁘면 지는** 경우이고,
자주 나오는 것이 뜨면 **진짜로 불리한** 대면이다.

`--봤다` 로 실제로 본 기술을 넣으면 확률이 100%로 고정돼서 범위가 좁아진다.

```
아무것도 모를 때     승률 96.3%
얼음엄니를 봤을 때   승률 20.4%
```

> 기술 채용률의 합이 포켓몬마다 평균 **376%** 다. 기술칸이 4개이므로 채용률을
> '그 칸에 들어 있을 확률' 로 그대로 쓸 수 있다는 뜻이다. 다만 칸 수 제약 때문에
> 그냥 뽑으면 어긋나서, 조건부로 직접 뽑는다 (재현 오차 1.1%p).

## 계산기가 반영하는 것 / 못 하는 것

**반영함**

- 실능 계산 (종족값·노력치·성격·랭크 변화)
- 타입 상성, 자속, 급소, 데미지 난수 16단계
- 화상일 때 물리 반감
- 특성 — 스카이스킨류 4종, 천하장사, 의욕, 적응력, 테크니션, 단단한발톱,
  스나이퍼, 심록·맹화·급류·벌레의알림, 두꺼운지방, 내열, 건조피부, 필터, 하드록, 파동의방호
- **무효화 특성** — 부유, 천정부지, 축전, 피뢰침, 저수, 건조피부, 초식, 그리고 이를 뚫는 배짱
- 도구 — 생명의구슬, 힘의머리띠, 박식안경, 달인의띠, 타입 강화 도구, 반감 열매
  (타입 강화 도구와 반감 열매는 게임 설명문에서 자동으로 읽어내므로 새 도구가 나와도 따라온다)

특성은 데미지 관련 110개 중 **42개가 계산에 반영**돼 있고, 17개는 반영은 안 되지만
경고로 알려준다. 「베는 기술」「펀치 기술」 같은 분류는 게임 원본 데이터에서 뽑아냈다
(`moves.json` 의 `tags`).

**아직 못 함**

- 날씨·필드·리플렉터·빛의장막
- 여러 번 때리는 기술, 반동·회복, 위력이 변하는 기술 (공격기 335개 중 79개)
- 따라큐의 「탈」, 브리두라스의 「지구력」 같은 여러 턴에 걸친 특성
- 상태이상 입력은 화상만

못 하는 특성이 걸려 있으면 계산 결과에 `!` 경고가 뜬다.
`best.py` 는 여기에 더해 **위력 숫자를 믿으면 안 되는 기술 55개**도 `!` 로 표시한다.
자세한 점검 결과는 [docs/ai-design.md](docs/ai-design.md) 2장에 있다.

> 챔피언스에는 **구애하치마키·구애안경·돌격조끼가 없다.** 대신 힘의머리띠(물리 1.1배)와
> 박식안경(특수 1.1배)이 있다. 본편 감각으로 계산하면 틀리니 주의.

## 사용률을 갱신하는 방법

1. `..\pokemon_dashboard\scrape.bat` 실행 — champs.pokedb.tokyo 에서 새로 수집 (5분쯤)

## 데이터 출처 — 섞지 말 것

**두 곳에서 오고, 역할이 다르다.**

### 게임이 정한 것 → `projectpokemon/champout`

<https://github.com/projectpokemon/champout> (MIT 라이선스)

게임 파일에서 직접 뽑아낸 원본이다. 한국어 텍스트도 게임에 들어있는 그대로다.
종족값·타입·특성·기술 제원·도구가 여기서 온다.

> 주의: ProjectPokemon 이라는 단체 자체는 챔피언스 전용이 아니다. 저장소가 24개 있고
> 대부분 다른 게임(3~5세대, 포켓몬 GO, 레전드 Z-A)용이다. **`champout` 저장소만** 챔피언스다.

### 사람들이 실제로 하는 것 → 로토덱스

`../pokemon_dashboard` (champs.pokedb.tokyo 수집본)

싱글 랭킹, 기술·특성·성격·도구·노력치의 **채용률 %** 가 여기서 온다.
게임 파일에는 "사람들이 뭘 쓰는지"가 있을 리 없으므로, **이건 champout으로 대체 불가능하다.**

### 타입 상성표 → 직접 검증한 표

`../pokemon_type_synergy/types_data.py`

챔피언스 상성표는 본편과 다른 부분이 있다(예: 드래곤이 전기를 반감하지 않음).
인터넷에 도는 챔피언스 상성표 중에는 **본편 것을 그대로 복사한 가짜**가 있으니 주의.
(구별법: 타입이 19개이고 "스텔라"가 들어있으면 본편 복사본이다. 챔피언스는 18개다.)

## 확인해 둔 게임 규칙

### 대전 형식

**6마리 파티에서 3마리를 선출한다.** 6대6이 아니다.

이것 때문에 대전이 시작되기 전에 이미 한 번 "서로의 6마리를 보고 동시에 3마리를 고르는"
결정이 일어난다. 조합은 `6C3 = 20` 이라 양쪽 합쳐 400가지 — 전부 훑어볼 수 있는 크기다.

3마리뿐이라 **교체할 여지가 적고**, 그래서 강제로 바꾸게 만드는 수(하품 · 날려버리기 ·
울부짖기)의 값어치가 크다. 거꾸로 스텔스록 같은 압정을 본편 6대6 감각으로 재면 과대평가가 된다.

> 사용률 데이터에는 `rank` 만 있고 **선출률이 없다.** 그 rank 가 파티 채용 기준인지
> 선출 기준인지도 아직 확인 못 했다. "상대로 만날 확률" 을 쓰려면 선출 기준이 맞다.

### 능력치 계산 (레벨 50)

챔피언스는 노력치 체계가 바뀌었다. **능력치당 최대 32, 총합 66.**
이 숫자는 "능력치에 그대로 더해지는 값"이다.

```
HP     = 종족값 + 75 + 노력치
그 외   = (종족값 + 20 + 노력치) × 성격보정        ← 소수점 버림
```

성격 보정은 1.1 / 1.0 / 0.9.

> 예전 노력치(0~252)와의 관계는 `예전 = 지금 × 8 − 4`.
> 종족값 1~255 × 노력치 0~32 조합 25,245가지를 기존 공식과 전부 대조해 확인했다.

### 데미지 비율 (레벨 50)

```
데미지 비율 = 22 × 기술위력 × 공격실능 ÷ 방어실능 ÷ 50 ÷ HP실능 × 난수
```

난수는 0.85 ~ 1.00 (16단계).

### 결정력 / 내구력

한 방에 죽는지를 숫자 하나로 비교하기 위한 지표.

```
결정력 = 공격실능 × 기술위력 × (자속·특성·상성·랭크 등 배율)
내구력 = HP실능 × 방어실능
```

| 조건 | 결과 |
|---|---|
| 결정력 ≥ 내구력 ÷ 0.374 | 확정 1타 |
| 결정력 ≈ 내구력 ÷ 0.407 | 약 50% |
| 결정력 < 내구력 ÷ 0.44 | 확정 2타 이상 |

0.44 = 22÷50, 0.374 = 0.44×0.85 로 정확히 떨어진다.
(나무위키에는 50% 지점이 0.411로 적혀 있는데, 실제로 계산하면 43.75%다. **0.407이 맞다.**)

### 성격 보정

성격 25개의 능력치 보정은 게임 내부 순번에서 나온다.
**올라가는 능력치 = 번호 ÷ 5의 몫, 내려가는 능력치 = 번호 ÷ 5의 나머지** (순서: 공격·방어·스피드·특공·특방).
몫과 나머지가 같으면 무보정(5종).

실제 사용률 데이터로 확인함: 1위 성격이 올려주는 능력치가 1위 노력치 배분과
일치하는 비율 90.1%, 성격이 깎는 능력치가 '안 쓰는 공격 능력치'인 경우 263마리 중 245마리.

### 아직 확인 못 한 것

실능 계산식과 개체값 체계는 **게임 화면과 대조해 확정됐다** (2026-09-17, 6/6 일치).
개체값은 없거나 전부 최대로 고정이다.

남은 것은 능력치 화면으로는 알 수 없고 **실제 대전의 숫자를 봐야** 하는 값들이다.

- 자속 보정 1.5배 / 급소 배율 1.5배 — 자속 기술 한 번, 급소 한 번이면 확정된다
- 화상 시 물리 반감 0.5배
- 마비 시 스피드 0.5배 — 이건 데미지가 아니라 순서로 확인한다

전부 `calc.py` 의 `CONFIG` 한 곳에 모여 있다. 자세한 것은
[docs/ai-design.md](docs/ai-design.md) 4장.

## 게임 데이터 코드값 의미

기술 512개를 다른 출처와 교차 검증해서 확정했다 (불일치 0건).

- `category`: 0 = 물리, 1 = 특수, 2 = 변화
- `direct`: 1 = 접촉 기술
- 타입 순서: 노말, 격투, 비행, 독, 땅, 바위, 벌레, 고스트, 강철, 불꽃, 물, 풀, 전기, 에스퍼, 얼음, 드래곤, 악, 페어리
